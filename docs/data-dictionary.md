# Canonical data contract

UTF-8 comma-separated files; headers are required. Empty cells mean unknown, never zero. IDs are stable, case-sensitive strings; a player keeps the same ID across aliases and editions. Map aliases manually and retain provenance. Copy the headers in `data/examples/` into ignored `data/input/` for a private expanded dataset.

`matches.csv` has one row per completed competitive **1v1 series/tie**, not per leg. Do not mix aggregate ties with their constituent legs. Required fields: `match_id`, `date`, `game_edition`, `tournament_id`, `player1_id`, `player2_id`, `winner_id`, `loser_id`, `platform`, `tier`, `score1`, `score2`, `decision`, `source_url`. The optional `event_end_date` and `date_precision` preserve date uncertainty; use `date_precision=day` with an exact match `date`, or leave `date` empty and use a sourced `event_end_date` with `date_precision=event_end`. Event end dates are used only to establish cutoff eligibility. Optional `match_format` defaults to `1v1`.

Editions are `FIFA18` through `FIFA23`, then `FC24`, `FC25`, `FC26`. A season label is not a game release date. `decision` is `score` (decisive reported goals; period unspecified), `regulation`, `aggregate`, `extra_time`, `penalties`, or `draw`. Completed draws enter the played network and have no winner or loser; equal goal totals are required when both are known. The win network contains only decisive results. Scheduled matches, forfeits/walkovers and team formats are excluded with a recorded reason. Goals may be empty; penalty shootout scores are not regulation goals. `platform` is event-specific; a player's platform can change across editions. Under `research_event_scope_v1`, `world` and `major` enter the filtered sensitivity run and `regional` identifies domestic league events. These are research event categories, not official provider tiers. An absent tier is unknown. The enrichment fields `tier_scheme`, `tier_source_url` and `platform_source_url` retain the basis for coding. Provider tier schemes require an explicit reviewed mapping before comparison.

`players.csv`: `player_id`, `handle`, `country`, `region`, `source_url`. Country uses ISO alpha-2 when independently verified. Region is an explicit research coding, not inferred automatically from country. Unknown metadata stays empty. Club/platform temporal histories should be supplied separately when needed for later RQs.

`earnings.csv`: `player_id`, `scope`, `game_edition`, `earnings_usd`, `as_of`, `source_url`. Scope is `career` (combined-network comparison) or `edition` (specified game-edition comparison). Each row is a **total snapshot**, never one tournament payout; aggregate tournament payouts first, avoiding overlapping totals. Use one record per player/scope/edition/as-of date. The most recent snapshot at or before the analysis cutoff is used. Current career totals without a historical snapshot cannot be used for a historical cutoff. Career totals can include earnings outside observed matches; describe this comparability limitation. Optional `coverage_status` and `measurement` distinguish provider-recorded incomplete career/edition totals; these and `source_url` propagate into rankings. A header-only file remains valid and produces insufficient-data statuses. Current public data contains real earnings snapshots; no missing observation is imputed as zero.

Duplicate match IDs, unknown players, inconsistent winners/scores, malformed dates and unsupported editions stop the pipeline after a quality report is written. Different IDs can still refer to the same real-world tie: the curator must resolve cross-source duplicates before import. Each match must have an HTTPS provenance URL.

Edges: the win graph is loser -> winner and its weight counts won ties. The played graph is undirected and its weight counts played ties. In-degree is distinct opponents beaten; incoming strength is total wins. Reciprocal wins form two directed edges but one played edge. Only participating players enter each network.

Reviewed event metadata lives in `tournaments.csv`; `profile_attributes.csv` carries player_id, country, source_url and as_of for current provider country flags. Country enrichment respects the cutoff, never infers circuit regions, and retains conflicting original observations with a warning.
